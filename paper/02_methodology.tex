\section{Methodology}
\label{sec:methodology}
The repository implements four layers: model preparation, integer conversion, HTTP serving, and container packaging. The intended path is MobileNetV2 with a $224\times224\times3$ input, conversion to a fully integer TensorFlow Lite model, and single-image inference through a FastAPI endpoint.

\subsection{Model preparation and quantization}
The baseline factory constructs ImageNet-pretrained MobileNetV2. The optional pruning module configures unstructured magnitude pruning with TensorFlow Model Optimization's polynomial schedule from zero to 30\% target sparsity over 1,000 steps. This operation masks individual weights; it does not remove entire channels. A training loop with pruning callbacks and evaluation is required before stripping the wrappers. Such a trained pruning artifact is not included, and neither achieved sparsity nor pruning speedup is established here.

For post-training quantization, the converter is configured with \texttt{Optimize.DEFAULT}, the built-in INT8 operator set, and INT8 input and output tensors. A representative calibration set is required. Random arrays are not accepted as evidence of calibration quality; the conversion scripts require an image directory through \texttt{EDGE\_CALIBRATION\_DIR}. Each image is decoded, converted to RGB, resized to $224\times224$, and normalized using MobileNetV2 preprocessing before being yielded to the converter. The affine mapping is
\begin{equation}
q=\operatorname{clip}(\operatorname{round}(x/S)+Z,q_{\min},q_{\max}),
\end{equation}
where $S$ and $Z$ are the scale and zero point determined by the converter; dequantization uses $\tilde{x}=S(q-Z)$.

\subsection{Serving and packaging}
The service exposes \texttt{/health}, \texttt{/metadata}, and \texttt{/predict}. Input preprocessing reads the tensor's actual quantization parameters rather than assuming that all INT8 models use the same offset. Output scores are dequantized when metadata are available. If no model is loaded, the service reports a degraded health state and returns an error from \texttt{/predict}; it does not silently fabricate predictions. This distinction is important for deployment monitoring and for honest benchmark collection.

Docker packages the service with the standalone TFLite runtime, Pillow, NumPy, and the web server. Docker Compose provides a model volume and CPU/memory limits. These limits are deployment policy, not measurements: their effect must be evaluated on the target device using repeated runs, warm-up rules, and a declared measurement tool.

\subsection{Reproducibility protocol}
For a publishable evaluation, the benchmark should record the exact model hash, TensorFlow/TFLite runtime version, operating-system image, CPU governor, thread count, input set, warm-up count, number of timed repetitions, mean and percentile definitions, and power-meter model. Accuracy must be evaluated against a fixed labeled validation set; latency and memory must be measured separately for native inference and HTTP serving. Derived energy is computed as $E=P\,t$ only when $P$ is a measured average power over the corresponding interval.
