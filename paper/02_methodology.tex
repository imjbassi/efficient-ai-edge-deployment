\section{Methodology}
Our proposed deployment pipeline consists of three interconnected stages: structural pruning, mixed-precision quantization, and hardware-aware containerization. Unlike traditional sequential pipelines, our approach uses the constraints of the final deployment container to inform the pruning and quantization parameters iteratively.

\subsection{Structural Pruning and Quantization}
We apply structured pruning to eliminate redundant channels within convolutional layers, targeting a predefined sparsity threshold that aligns with the cache size of the target hardware. Following pruning, we employ Post-Training Quantization (PTQ) to map 32-bit floating-point (FP32) weights and activations to 8-bit integers (INT8). To mitigate accuracy degradation, we utilize a calibration dataset to optimally determine the scaling factors for the INT8 tensors. 

\subsection{Hardware-Aware Containerization}
Edge devices frequently suffer from overhead introduced by standard containerization. We mitigate this by using minimal, multi-stage Docker builds equipped with specialized lightweight runtime binaries. For devices with embedded GPUs, the container is configured with direct hardware passthrough to minimize abstraction penalties.

\subsection{Differentiating from Standard Runtime Optimization}
Industry-standard edge deployment frameworks, such as TensorFlow Lite (TFLite) and NVIDIA TensorRT, provide robust post-training quantization and kernel optimizations. However, these tools generally treat the model and the deployment container as isolated entities, often suffering from I/O bottlenecks during CPU-to-GPU memory migration on edge devices. 

Our pipeline distinguishes itself by integrating custom CUDA kernels and asynchronous CUDA streams directly into the containerized runtime. Rather than relying on generic execution graphs, our framework actively overlaps data transfers with computation to maximize hardware utilization. By profiling the exact memory limits and scheduling constraints of the target Docker environment, the pruning and quantization phases iteratively adjust the model's sparsity and precision. This ensures that the packaged model does not merely execute successfully, but maximally utilizes the specific cache hierarchies of the target hardware—a capability not natively exposed by standalone TFLite or TensorRT workflows.
