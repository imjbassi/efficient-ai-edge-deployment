\section{Introduction}
\label{sec:intro}

Executing inference near the data source can reduce network dependence and response time, but edge devices impose tight limits on storage, memory, computation, and power. Deployment therefore includes both model transformation and software packaging. A small artifact that cannot be reproduced, loaded, or monitored is not a complete edge system.

Integer post-training quantization maps floating-point weights and activations to eight-bit representations and can reduce model size while enabling integer kernels \cite{jacob2018quantization,tflite_integer}. Compact architectures such as MobileNetV2 complement this transformation through depthwise separable convolutions and inverted residual blocks \cite{sandler2018mobilenetv2}. Prior benchmark efforts have also shown the need to report latency, memory, and accuracy under explicit hardware and software conditions \cite{banbury2021mlperf}.

This work contributes a public, executable artifact rather than a new quantization algorithm. The artifact (1) downloads a checksum-verified evaluation dataset, (2) converts one pretrained graph to FP32 and full-integer TFLite formats, (3) evaluates both formats with identical preprocessing and labels, (4) records raw timing samples and provenance, and (5) exposes the optimized model through a bounded inference API and container. The central question is practical: what changes when precision is reduced while the architecture, dataset, preprocessing, runtime family, and thread count are held fixed?
