\section{Introduction}
\label{sec:intro}

The rapid increase in Internet-of-Things (IoT) devices and the introduction of 5G technologies are shifting immense computational workloads from centralized cloud servers to edge devices. It is estimated that a vast majority of enterprise-generated data will soon be created and processed at the network edge rather than in cloud data centers. This paradigm shift is driven by the critical need for low-latency, real-time inference, and robust data privacy. Processing data directly on edge hardware eliminates cloud round-trip latencies, network bandwidth bottlenecks, and security vulnerabilities associated with transmitting sensitive information. Immediate, local AI-driven decision-making is vital for real-time autonomous systems, robotic controllers, and smart city infrastructure.

Despite these advantages, deploying modern deep neural networks (DNNs) on resource-constrained edge hardware is extremely difficult. State-of-the-art models are characterized by millions, and sometimes billions, of parameters, making them exceptionally resource-hungry. For example, a baseline ResNet-50 model \cite{he2016deep} requires approximately 168\,MB of storage for 32-bit floating-point (FP32) weights, which is a major strain on embedded devices with only 1--2\,GB of RAM. At the edge, hardware platforms typically rely on low-power mobile CPUs or highly specialized, small-footprint accelerators under strict thermal and battery-power envelopes. When unoptimized models are deployed, they suffer from unacceptable latency, high memory pressure, and excessive energy consumption.

To overcome these constraints, joint research and industrial efforts have turned to model compression techniques and tailored edge packaging. Model compression techniques---including post-training quantization (PTQ) \cite{jacob2018quantization}, structured and unstructured weight pruning \cite{han2016deep, li2017pruning}, and knowledge distillation---effectively trim redundant calculations and parameters, making models suitable for edge memory limits. Standard 8-bit integer (INT8) quantization, for example, shrinks the model's storage footprint by up to 4x and dramatically boosts execution speeds on instruction-optimized CPUs. 

Concurrently, modern edge software MLOps frameworks have advanced containerized deployments to enforce consistent, reproducible runtimes across heterogeneous hardware nodes. Container technologies, such as Docker, isolate application workloads and dependencies, resolving ``dependency hell'' at the cost of slight system overhead. When coupled with hardware-optimized runtimes like TensorFlow Lite (TFLite) \cite{warden2020tensorflow} or ONNX Runtime, optimized model artifacts can directly target specialized execution units (such as ARM NEON or NVIDIA Jetson GPU kernels).

In this work, we propose a comprehensive, end-to-end engineering methodology that co-optimizes model-level compression with system-level containerized packaging. Our target deployment pipeline first performs weight pruning and full INT8 post-training quantization to construct highly compressed artifacts. It then packages the model with a dedicated FastAPI serving microservice inside a lightweight Docker container, constrained by resource limits. Using MobileNetV2 \cite{sandler2018mobilenetv2} as a case study, we empirically evaluate this approach on physical hardware (e.g., Raspberry Pi 4), tracking throughput (FPS), RAM usage, latency, and simulated energy consumption.

The remainder of this paper is organized as follows: Section~\ref{sec:methodology} reviews the model compression and edge containerization methodology. Section~\ref{sec:benchmarks} presents the empirical hardware results and compares FP32 against INT8 TFLite profiles. Section~\ref{sec:conclusion} concludes with a summary of edge MLOps findings and outlines future directions.
