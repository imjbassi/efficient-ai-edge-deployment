\section{Results}
\label{sec:results}

Table~\ref{tab:results} reports the complete validation and host-latency experiment. The FP32 model is 13.34 MiB and the INT8 model is 3.81 MiB, a 71.5\% reduction or 3.50$\times$ compression. Mean latency decreases by 24.3\%, from 8.53 to 6.46 ms, corresponding to a 1.32$\times$ speedup. The median and 90th-percentile values show the same direction.

The top-1 accuracy difference is 0.92 percentage points. FP32 top-1 accuracy has a Wilson 95\% interval of 65.24--68.18\%; INT8 has an interval of 64.31--67.28\%. Top-5 accuracy changes by 0.94 percentage points, from 90.75\% to 89.81\%. These results indicate that the calibrated integer model closely tracks the floating-point model on this subset, while the overlapping intervals caution against interpreting the observed difference as a general ImageNet accuracy estimate.

\subsection{Reproducibility and limitations}

The result JSON stores all 500 raw latency observations, per-class accuracy counts, model hashes, runtime versions, dataset hash, calibration count and seed, preprocessing, and thread settings. The experiment can therefore be repeated or reanalyzed without transcribing values from the manuscript.

Three limits constrain interpretation. First, Imagenette covers only ten ImageNet classes, so the accuracy estimate does not replace evaluation on the 50,000-image ImageNet validation set. Second, the latency result describes one x86-64 host and one thread. ARM CPUs and accelerators may produce different speedups. Third, preprocessing, HTTP transport, resident memory, container overhead, temperature, and power are outside the timed region. Claims about those quantities require separate, synchronized measurements on each target device.
